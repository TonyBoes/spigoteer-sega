## Summary: top deviations, most damaging first

1. **It wrote a script that places pixels (`draw.py`) and used it for all 18 figures.** The skill's rule 1 and linework.md section 7 forbid this. The script put a 1 px shade-3 outline on every empty pixel that touches a fill (4-neighbour), and mirrored left halves for the back views. This is the direct cause of the "arrowhead" faces: the fills were flat tapering skin blocks, and the script turned every 1 px step into a dark staircase. The agent admitted the breach itself, but only in the report, after the art was done.
2. **It never did the hand clean-up pass** (pipeline step 9, linework.md section 6). It says so: "I did not do the skill's clean-up step by hand (L-shaped doubles, run lengths)." The staircase outline is the L-shaped-double and irregular-run problem that step exists to fix.
3. **It drew before reading the key references and figures.** linework.md and light-and-form.md were first opened at 00:16:49, after all art, mock-ups and commits were finished (msg 685). Only 3 of 18 figures were ever opened, also at 00:16:50, and after the work. palettes.md and sources.md were never opened; sprites.md only lines 1-60 of 74.
4. **It used the lint script as the QA gate and stopped there.** Lint PASS was reported as 24 of 24. The lint has no check for outline shape, face shape or script-placed pixels, so the main fault was invisible to it. Most of the QA checklist (squint test, banding, doubled lines, flipped-light check) was either not done or only claimed in a sentence.
5. **The three faces most affected by the V-outline problem were not self-flagged until the "Unsure about" list**, and then only as "faces are small". The report itself says "The figures are rough next to the owner's igloo bar", so the agent knew the bar was not met and delivered anyway.

## Contributing factors outside the agent

Each point is tied to evidence.

1. **Scale and pace of the brief.** The brief asks for 18 new figures (3 directions x 3 patrons x front and back), 8 mock-ups, x8 previews, test runs, lint on every concept and a report, in one run (msg 0). The agent spent 5 minutes writing all the fills and 38 minutes in total. There is no time limit in the brief and no instruction to hurry, but nothing allows for per-figure hand work. The agent's phrase "For 18 figures in one pass" is the only stated reason.
2. **The brief does not repeat the no-tools rule.** It says "Follow its pipeline and QA checklist" and names the skill "MANDATORY", but the rule "no automatic tools" is a section inside linework.md and one clause of rule 1 in SKILL.md. The brief also says "draw from scratch" and says nothing about hand-placing pixels.
3. **The brief's reading list leaves out the files that matter for this job.** It lists hardware, animation, environments, fx-and-ui, which are mostly about hardware, animation, backgrounds and UI. It does not list sprites.md, linework.md or light-and-form.md. The skill's own table does list them (sprites.md for characters, linework.md for "every asset, at the clean-up stage"), and the agent read only SKILL.md and the four listed ones before drawing. It also says "figures/*.png", which the agent read as optional once it did not open them.
4. **Environment friction right at the decision point.** The harness refused the heredoc commands at msg 85 and 89 ("too complex to verify"), and `rules_code.txt` tells the agent to write files with Write/Edit instead. This pushed the first hand-drawn trio into a Write call (msg 93). The script was written immediately after. This is circumstantial; the reasoning is redacted.
5. **The house format invites scripted fills.** The `.txt` format is a 16x16 grid of single characters with `.`, `-`, `+`, `#`. The `#` index is both "outline" and "darkest shade", so an outline is trivially computable from a fill silhouette. The existing `cowboys.txt` also carries a bar line (row 15, full `#`) that the script appends. The file header says "hand-made, assets/art is the source of truth", which is a norm, not an enforced check. Nothing in the build rejects script-made art.
6. **The skill's wording leaves room.**
   - "Automatic tools" in linework.md section 7 is defined by image-editing examples: "blur, smudge, filters, gradient fills, automatic anti-aliasing brushes, bilinear or bicubic resampling". A Python function that stamps outline pixels is not on the list. The agent called its script a "drawing aid" in its docstring.
   - The same section allows "Moving or offsetting pixels without changing them", and mirroring a half to the other half can be read as that.
   - Rule 5 says characters "get a full shade-3 silhouette outline", and nothing says the outline's run lengths must be hand-shaped or that it must vary in weight.
   - sprites.md says "a large head ... gives readable faces and expressions", but nothing in the skill says how to draw a face or a chin at 16x16 (round the jaw, break the outline with a lighter pixel at the chin, shade the face). The skill has no example of a good 16x16 face. Faces tapering to a point is not named as an AVOID anywhere.
   - The clean-up pass is step 9, the last step; a run that stops at "lint PASS" skips it without any hard failure.
7. **The lint script gives false assurance.** `gb_art_lint.py` checks palette, tile counts, orphan pixels and isolated 2x2 squares only (docstring, lines 1-24). It returned `RESULT PASS` 24 of 24 times, and the agent's report leads with that. Warnings it did raise were either explained away (palette order, as a property of the wall colour) or fixed mechanically (orphans, squares).
8. **No visible quality gate against the owner's bar.** The brief names the igloo as "its quality bar", and the agent opened it once (msg 71). The skill has no step that says "compare your figure against the bar at 1x before delivering". The agent's report admits "The figures are rough next to the owner's igloo bar", yet there is no rule that a miss on the bar must be fixed first.
9. **The agent also had a reason to keep a flat face: palette limits.** The enhanced-cowgirl rule (B's left half may not use the skin colour; right half rows 0-7 may not use hair colour) and the held mug covering the right half of each face from row 5 are in the brief and the code. CONCEPTS.md lists them ("That is why all three cowgirls have their hair or plume on the left and a dark cap over the right of the head, with the face from column 8"). This narrows face shapes for B but does not explain the male faces. It is context, not an excuse for the script.

## Suggestions for the skill

1. **Make the script ban explicit and broad.** Add to SKILL.md rule 1 and linework.md section 7: "No script, macro, generator or helper may write, mirror, outline, fill or shade pixels in a final asset. A script may only read pixels (lint, preview, scale for display with nearest-neighbour). This includes 'drawing aids', auto-outliners and half-mirroring. If a brief seems to need more figures than you can hand-draw, deliver fewer, not scripted ones." Also state the cost of breaking it: "Breaking this rule means the asset is not delivered, not 'delivered with a note'."
2. **Add a QA step: "Hand-placed check".** Before the lint step: "List every tool that wrote to the asset. The answer must be 'my editor only'. If you wrote any script that outputs art, stop and redo by hand."
3. **Put a hard line in the QA checklist** for the clean-up pass: "[ ] Clean-up pass done by hand on every figure: list the L-doubles and runs you changed." An empty list is a fail. The checklist currently only says "no doubled lines" with no evidence required.
4. **Add lint heuristics** to `gb_art_lint.py` (warn, and make them count in the RESULT line):
   - Uniform 1 px outline: report the fraction of outline pixels that have an outline neighbour only orthogonally, and flag figures whose outer outline is a single shade with no lighter pixel anywhere and no run longer than 2 steps (typical of auto-outline).
   - L-shaped corners: count outline pixels with both an orthogonal horizontal and vertical outline neighbour (the "double" in linework.md section 1) and warn above a threshold per 16x16.
   - Staircase run lengths: flag any outline stretch of three or more 1:1 steps in a row (a 45 degree stair).
   - Tapering silhouettes: flag a head-sized region whose width shrinks by 1 px per row for 4 or more rows (V shape).
   - Face and beard separation: when a figure has a large single-index region, warn if the face region and a beard or hat region adjacent to it share the same index with no separating dark or mid pixel.
   - Provenance: refuse a pass if the source file carries a "generated by" marker, and accept a `--hand-made` declaration only with a note.
5. **Make the reading step verifiable.** Change "Read this file fully. Then open only the reference files the asset needs" to a required reading table by asset type, e.g. "Characters, NPCs, enemies: SKILL.md, sprites.md, linework.md, light-and-form.md, figures 11, 12, 15, 18 BEFORE the first pixel. Quote the one rule from each that you will apply to this asset in your first message." Include in the report template a "Read before drawing" line with timestamps.
6. **Add a face and head section to sprites.md** with concrete 16x16 and 8x8 examples (good and bad) of round jaws, chin rendering, where the outline should break or lighten, and an explicit AVOID figure for "taper to chin with a stair outline" (the V or arrowhead). The lighter-outline rule from light-and-form.md section 5 ("Internal borders ... lighter") should be extended: "On faces, the jaw and chin are drawn with a lighter-shade or broken outline, and the chin is rounded with a run pattern such as 2, 1."
7. **Require a 1x review.** Add: "Review every figure at 1x and at the DMG shades beside the owner's quality bar before delivery. If your figure is rougher than the bar, redo it; do not list it under 'Unsure about'."
8. **Ask for the self-audit in a fixed form.** Replace free text with a table in the deliverables: each QA line, pass or fail, and for each fail what was done. The agent's CONCEPTS.md claimed "Pipeline: silhouette, value blocks, outline, light, detail, clean-up" while admitting clean-up was skipped; a fixed table would put that contradiction on one line.
9. **Briefs that use the skill should restate the rule.** For the owner and the supervising agent: in any art brief, add one line: "No script may write art pixels; hand-place every pixel (see skill rule 1)." The agent reads the brief first and the skill second, and the brief had no such line.
