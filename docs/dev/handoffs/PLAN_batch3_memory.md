## 2. Bytes
Layout today (render.c:178-188, mirror.c:127-140, game.h:88-100): looks v 0..2 x 8 slots (shift 0..7) = 24 poses; variant 3 aliases look 0 (`v == 3 ? 0 : v`). A front pose is 6 tile ids, row order top t, t+2, t+4, bottom t+1, t+3, t+5 (stamp3 render.c:192, QI6 render.c:634).
- Table: 24 poses x 6 = **144 B**, indexed by a record offset (pose * 6, max 138).
- DMG mixed levels: **still 144 B, not 288.** The R set is built by `dmg_mixed` (mirror.c:~141) into the odd-shift slots of the same 144 tiles; st_tab's R half (`st_tab[32 | v<<3 | s]`, mirror.c:138) just points at another record of the same table. 2x only appears if the art is compacted (section 7 rule 3).
- `st_tab` (64 B, render.c:178): KEEP. It becomes (dir, look, shift) -> record offset (a lookup without a multiply by 6 in the hot path). Freeing it would cost a mul-by-6 per stamp; 64 B is not worth the C-ROM perf. It stays in render.c's _DATA; it is also the symbol tests read (tests/test_classic.py:283).
- `id_seq` (ROM0, render.c:636, 144 B): freed. `quick_entries` (render.c:648) then reads `pat_tab + st_tab[..]`.
- Net: WRAM 0 new (`scene_ram` replaces 395 B of statics; table uses 144 of them, 251 B stay free). ROM0 +144 B minus code growth (est. +20..40 B for per-cell reads in stamp3 / put_col / quick_mirror). ROM data per group: 0 with legacy ids (the table is filled by formula in `mirror_load`, which already loops v, s with `music_pump`).
- Budgets to record at each step (`romusage build/game.map`, main's map today: ROM_0 794 free, WRAM_LO 160 free, WRAM_HI_0 461 free; the handoffs say ROM0 453 asm / 70 C: re-measure at step 0, the two do not agree).

## 3. Mechanism (chosen): byte array + offset macros, not a union, not a pointer alias
- story.c: replace the five statics by `uint8_t scene_ram[SCENE_RAM_N];` (395) and macros in story.c: `#define pt (*(portrait_t *)(scene_ram + SR_PT))`, `pt_map (scene_ram + SR_MAP)`, `pt_attr (scene_ram + SR_ATTR)`, `spk_bg (scene_ram + SR_SPKB)`, `spk_obj (scene_ram + SR_SPKO)`. Constant addresses: SDCC emits the same code as for the statics. The table sits at the END of the block (SR_PAT = 251, 144 B, ends at 395) over the tail of pt_map / pt_attr / spk; `pt` stays at offset 0. A scene overwrites all of it anyway, and the diff to the `pt` users stays zero.
- game.h: `extern uint8_t scene_ram[395]; #define PAT_TAB (scene_ram + SR_PAT)`. `PAT_TAB_N 144`, `SR_PAT` and the scene offsets in scratch.h (a new section "scene_ram", with `typedef char` asserts like the fight ranges: pt+pt_map+pt_attr+spk <= SR_PAT is NOT required, the overlap is the point; assert instead `SR_PAT + PAT_TAB_N <= SCENE_RAM_N` and `SCENE_RAM_N == sizeof(portrait_t) + 2*81 + 2*STORY_MAX_SPK`).
- Why not a named `union { struct scene_bufs; uint8_t pat_tab[N]; }`: the macros are needed for the struct members anyway (every `pt.` use), and a union type needs to be visible in render.c / mirror.c / game.h. A byte array is the project's idiom (`story_scratch`, `MG`, `OL`, `CR`), is one symbol for the layout rig, and tests/test_scratch_map.py already knows how to read offsets from scratch.h.
- Why not `#define MG ((union mg_ram *)story_scratch)`: story_scratch is the wrong block (section 6).
- Layout rig: `tools/data_layout_check.py` compares asm and C `.noi` symbol by symbol; both builds compile the same story.c / render.c, so `_scene_ram` is identical. `tests/asm_rig.py` compares WRAM diffs as offsets: valid while that passes; no asm routine reads st_tab or the table today (the asm in render.c is copy_n :36, copy_2rows :64, vq_exec :436; mirror.c :176 is `mo_range`; lift.c asm reads `patron_variant` and fixed `lift_tile` OBJ ids, not the table). Stamp, quick_entries and quick_mirror are C in BOTH builds, so no C twin work and the C-ROM perf is the same code as the asm ROM's.
- Symbols that disappear (`_pt`, `_pt_map`, `_pt_attr`, `_spk_bg`, `_spk_obj`): no test, tool or asm names them.
- Add to tests/test_scratch_map.py: a second USERS/GROUPS family for `scene_ram` ("a venue scene": pt, map, attr, spk; "a level": PAT.TAB) with the rule that the two groups are never alive together, and an entry for the offsets read from scratch.h.

## 4. Lifetime, writers, junk-RAM rule
- Single writer: `mirror_load(dirs)` (mirror.c:~104, BANKED, LCD off). Called from `start_level` (level.c:182, after `load_venue`, `load_patron_group`, `lift_level_init`, `enhance_load`) and `title_enter` (title.c:477, dirs 0; harmless: the title does not stamp patrons from the table, and the title scene buffers are a different block). It fills `PAT_TAB` by formula (legacy ids: record n cells = PATRON_TILE_BASE + pose + {0,2,4,1,3,5}; the same formula as `pose()` mirror.c:~117 and QI6), then st_tab as today but with record offsets, then (mixed DMG) `dmg_mixed()`. It must run before `place_start_patrons()` (level.c:183): already so.
- Table content does not depend on `dirs` with legacy ids (R and L records differ only through st_tab). One build per level, ~24 x 6 byte writes (+ the existing `music_pump` per variant), well inside the LCD-off load.
- Events that must leave the table valid, and why they do:
  1. Level start, any mode (STORY shift, boss fight, BOSS RUSH `rush_fight`, ARCADE next level, CLASSIC, LEVEL harness, debug select): `enter_level_screen` -> `start_level` -> `mirror_load`. Rebuilt.
  2. Return from a cut scene: always a new level load (PRE scene -> `venue_start` -> `step_start` -> `shift_start`; POST -> map -> next PRE) or a screen without the table. Rebuilt on the level.
  3. Return from a mini-game or the Pour-Off: `step_start` / `story_level_done` -> `shift_start` -> start_level. Mini-games lay `union mg_ram` over story_scratch, never over scene_ram.
  4. TRY AGAIN / life lost: `shift_start` / `resume_after_life` (main_cold.c:~270: same level, same group, table untouched; `shift_start` rebuilds). The frozen level under SP_FAIL keeps a valid table: nothing writes scene_ram.
  5. Pause / settings / pause card fades (trans.c, main.c): no scene_ram use.
  6. Mothership split (boss_mothership.c:357 `load_patron_tiles(cur_group, PATRON_TILE_BASE)`): same group, same ids with legacy layout: table unchanged. With a compacted layout (section 7) the loader must be the same one; no rebuild needed.
  7. Title, scores, bonus rounds (bonus.c/bonus2.c reuse the show tiles; `start_level` reloads, main_cold.c:228): the next level load rebuilds.
- Junk-RAM rule: nothing reads the table before `mirror_load` of that level has run (the LCD-off load precedes all stamping and VBlank queueing: `queue_quick` only drains quick_list entries added by play). Scene code initialises what it reads: `pt` by `portrait_get`, `spk_bg/spk_obj[i]` for `i < nspk` in `scene_enter` :476-481, `pt_map/pt_attr` by `compose_portrait` (full `w x h`) before any use, `cw = 0` / `story_cur = 255` in `portrait_now`. Test: poke 0xA5 over all 395 B before `start_level` (PyBoy zeroes RAM that hardware leaves as junk), then assert table == Python-built reference and the patron rows of a few frames equal a clean run.

## 6. If the story block is unsafe: fallback order (not expected to be needed)
Sizes from the audit (merged.txt): title.c buffers 182 B contiguous (d124 area; title-only: `title_enter` calls `mirror_load(0)` before the title initialises its buffers, so write order must be table first, title init after; every game start rebuilds); text-box block page_buf 56 + box_tiles 54 + tag_row 20 = 130 B contiguous (d285-d307) is 14 B short of 144 and `hud_buf` (d307) must stay; top_names 45 + top_scores 60 = 105 B contiguous (d799-d802) short of 144 and needs SRAM rereads in save.c / scores.c (title / list screens), plus scores.c ini_* 46 B (not adjacent). ## 7. The build batch: steps, tests, risk
Every step: `make`, `make cfall`, `make test`, `make check` on DMG and CGB (both ROMs); commit one step each; `tools/data_layout_check.py` after each. Never raise a perf guard; if one fails, stop and report. Goldens expected to change: **none** in any step (ids and pixels identical; nothing in this plan changes a tile).
0. **Baseline** (no commit): build, record `romusage`, run test_perf.py, test_half_rate.py, test_pause_card_fade (perf_arcade, classic_peak_real_rows, pause_card_fade) on asm and C ROMs. HANDOFF_batch2_steps.md lists C-ROM-only failures already at 37.1 vs 35 (perf_arcade[10-dmg]), pause_card_fade[0-cgb] 1.65 vs 1.6, classic_peak_real_rows[dmg-12], half_rate classic25 1439 vs 1440: re-measure; later steps must not be worse than this baseline.
1. **scene_ram** (story.c, game.h, scratch.h, tests/test_scratch_map.py): the five statics -> `scene_ram` with offset macros and asserts; table offset reserved, unused. Tests: story / scene / credits / dgag suites, `test_scratch_map` additions (static: disjoint within a group; the two groups declared never alive together). Files: src/story.c, src/game.h, src/scratch.h, tests/test_scratch_map.py. Perf risk: none (constant addresses; check the `.noi` / romusage code size delta = 0 +-4 B).
2. **Table fill, unused (st_tab unchanged)** (mirror.c, tests): `mirror_load` fills `PAT_TAB` by formula; st_tab keeps its first-tile meaning here (the switch to record offsets is step 3). New tests (tests/test_pat_tab.py): (a) table == Python reference for every group and every dir pattern (all L, all R, mixed, DMG and CGB); (b) junk poke over 395 B of scene_ram before start_level (levels, LEVEL harness dirs); (c) rebuild-after-scene: play a level, `story_debug_start` into a PRE scene (writes scene_ram), then a level: table intact; also after a mini-game and the Pour-Off return; (d) overlay safety: during PLAYING, a boss fight, a BOSS RUSH fight, TRY AGAIN, boss outro and pause, hash of the 144 B is unchanged over N frames, and no write to scene_ram (a PyBoy write hook / memory watch, or a canary byte in the 251 B spare that must stay); (e) the check that `scene_enter` is never reached while `game_state` is a level state (assert on a call-site watch). Perf risk: one 144 B fill per level load (LCD off, ~0.1 frame): none in play.
3. **Quick path** (render.c quick_entries, mirror.c st_tab fill, delete `id_seq`, tests/test_classic.py helper): st_tab = record offsets, `qv_src = PAT_TAB + st_tab[..]`, ROM0 +144 B. Test: existing quick redraw / classic tests; R-bar st_tab helper through the table; ROM0 free number recorded. Perf risk: quick_entries gets slightly cheaper (no subtract of the constant), the drain reads WRAM (like the existing `k = 32` shadow path, queue entries from WRAM already work in VBlank).
4. **Stamp and mirror paths** (render.c stamp_look / stamp3 / put_col / stamp / stamp_blank; mirror.c quick_mirror): per-cell ids from the record. HIGHEST perf risk: stamp3 changes from register arithmetic (`t, t+2, ..`) to six loads through a pointer in the compose loop (`compose_bar` stamps every patron of the dirty span; C in both ROMs). Measure test_perf / half_rate / perf_arcade vs step 0 BEFORE the rest of the suite. Mitigations in order: (i) copy the 6 bytes with an unrolled `*r++ = *q++` pair of rows (two pointers, no index math); (ii) keep a `t`-arithmetic fast path when the record is contiguous (a 3-byte bitmap of "contiguous" poses in the 251 spare bytes of scene_ram) and read the table only for exceptions; (iii) stop and report (asm for stamp3 needs the asm pass authorisation and a kept C twin; not assumed). Tests: every patron test, test_lift, test_enhanced, classic mixed levels, test_show; the goldens must be identical (pixels unchanged).
5. **Close-out** (docs): update HANDOFF_batch3.md status, the scratch.h header, tests' USERS table; record `romusage` before/after and the free 251 B in `scene_ram` (usable later for the Color-only extra looks, whose first tiles are computed by formula today). No code.
Out of scope of this plan (the tile compaction itself, a separate batch, decide after step 5): gen_art.py emits compacted ids plus a ROM descriptor, `mirror_load` copies it instead of the formula. Constraints found while tracing consumers, so the art batch does not break the memory work: (1) the shift-0 poses (12 tiles at PATRON_SHIFT0_OFS) and the 12 back views stay in legacy positions: title.c:494, po.c:154, dgag.c:409, credits `load_patron_pose0`, lift_tile and BOSS_BG_B read raw ROM offsets and 8x16 OBJ pairs; (2) no sharing ACROSS looks: BOSS_BG_A (boss.h:75) overwrites look C's 42 shifted tiles with the boss body, so any tile another look points at inside that range would be corrupted; sharing only toward the group's blank pair (PATRON_BLANK, look 0's shift-0 area) or within a look; (3) DMG mixed needs 72 distinct ids for the R set (odd-shift slots: 12 poses x 6): the odd-shift poses' tiles must stay private (not shared), else the flipped copies overwrite shared tiles; this halves the saving of the handoff's table (re-run tools/dev/patron_dups.py under rules 1-3 before deciding); (4) freed ids are holes unless the shifted region is renumbered, and renumbering fights rule (2) for look C; (5) ROM descriptor cost vs freed 16 B tiles: zoo (2 tiles = 32 B) barely breaks even, banks 1-8 have 17-83 B free.
